# status-sim

A prototype in the spirit of [Status – Sims But Social](https://socialai.app) (by
WishRoll): create a persona, drop into a fictional world ("era"), post to a feed,
and get reactions from AI-driven in-universe characters. Clout rises and falls
with what you post, and an energy system gates how often you can act. Tone is
unapologetically Gen-Z / internet-slang, including the copy and the characters'
reply voice.

## On real celebrities

This prototype does **not** use the names or likeness of real, identifiable
people anywhere, and no character ever generates a statement attributed to a
real person. That was a deliberate call: fabricated posts/DMs/comments
"from" a real celebrity, inside a social-feed UI, are the kind of thing that
gets screenshotted and mistaken for real — which is an impersonation and
defamation risk regardless of intent, and the type of feature that has
gotten other AI-companion apps into real legal trouble.

Instead, `main-character-era` is a fully fictional celebrity-culture world
(red carpets, paparazzi, clout that can vanish overnight) populated by
invented characters (`Coach Reyna Cole`, `Zayne Kroix`, `Peaches Monroe`) —
it gets you the fame fantasy without impersonating anyone real.

## AI-backed replies (optional)

By default, character replies come from local template banks
(`ARCHETYPE_REPLIES` in `app.py`), so the app runs standalone with zero
external calls. Set `ANTHROPIC_API_KEY` in the environment to turn on live,
in-character replies generated by Claude (`ai_backend.py`):

```bash
export ANTHROPIC_API_KEY=sk-ant-...
python app.py
```

To keep usage (and cost) low, only the **first reactor per post** uses the
live API (`AI_REPLIES_PER_POST`, default `1`); every other reactor, and any
post if the key is missing or the API call fails for any reason, falls back
to the template banks instantly — there's no user-facing failure mode. Model
used is `claude-haiku-4-5-20251001` with a 60-token cap per reply, so each
AI-backed post costs a small fraction of a cent. Replies generated live are
marked with a small ✨ in the UI so it's clear which are live vs. templated.

No key is committed anywhere in this repo — set it as an environment
variable locally, or as a repo/Actions secret if you deploy this.

## Run it

```bash
pip install -r requirements.txt
python app.py
```

Then open http://localhost:5050.

## What's implemented

- Persona creation (name, avatar, bio)
- 6 fictional worlds ("eras"), each with 3 recurring AI characters
  (mentor / rival / bestie archetypes) — including the celebrity-culture one
- A post composer that costs energy and gets reactions (likes + in-character
  comments, optionally live via Claude — see above)
- A clout meter with tiers: Cancelled → Nobody → Rising → Viral → Famous
- An energy economy: passive cap, "watch an ad" for a random top-up, a demo
  "premium" toggle that raises the cap
- Mobile-first, Gen-Z-flavored UI, installable as a PWA (manifest + service
  worker) so it can be added to a phone home screen like an app today

## Path to a real mobile app

The backend is a plain JSON API (`/api/*`), decoupled from the HTML/CSS/JS
frontend, so there are two straightforward next steps once the concept is
validated here:

1. **Fastest**: wrap this same web app with [Capacitor](https://capacitorjs.com/)
   or [Cordova](https://cordovaphonegap.com/) to ship it in the app stores
   with minimal changes.
2. **Native-feeling**: rebuild the UI in React Native / Expo, calling the
   same Flask endpoints (`/api/persona`, `/api/fandom`, `/api/post`,
   `/api/energy/*`). The reaction/clout/energy/AI logic in `app.py` and
   `ai_backend.py` would not need to change.

## Not implemented (out of scope for this prototype)

- Real user accounts / multiplayer rooms
- Real payments (the "premium" upgrade is simulated, no purchase flow)
- Any real, named public figures — see "On real celebrities" above
